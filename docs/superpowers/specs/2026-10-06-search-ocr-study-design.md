# Hybrid search, OCR, and study tools — design

**Date:** 2026-10-06
**Status:** Approved in conversation, pending written-spec review
**Builds on:** `2026-10-06-fullstack-rag-design.md` (current Folio app)

## 1. Goal and scope

Three additions to Folio, built and verified in this order:

1. **Hybrid search** — keyword search alongside vector search so exact terms
   (course codes, function names) retrieve the right chunks.
2. **OCR for scanned PDFs** — image-only pages become searchable instead of
   the document failing.
3. **Study tools** — generated multiple-choice **quizzes** and **flashcard decks**,
   saved per notebook, every item citing its source page.

**Stated by the user:** these three only (multiple chats, summaries/study
guides, notebook overview, and new source types are out of scope); study sets
are saved per notebook; generated from chosen sources plus an optional topic;
quizzes are multiple choice only.

**Constraints:** free services only; runs on one laptop; Groq free tier is
**8,000 tokens per minute and 1,000 requests per day** (measured for both
`openai/gpt-oss-120b` and `qwen/qwen3.8-27b`); no automated test suite —
each part is verified end to end.

## 2. Hybrid search

### 2.1 Schema (migration `0002`)

- `chunks.content_tsv tsvector GENERATED ALWAYS AS (to_tsvector('english', content)) STORED`
  — populated automatically for existing and new rows.
- `CREATE INDEX ix_chunks_content_tsv ON chunks USING gin (content_tsv)`.
- The ORM model declares the column as server-computed (never written by the app).

### 2.2 Retrieval

`similarity_search(db, notebook_id, query_text, query_embedding, top_k, document_ids=None)`:

1. **Vector list:** top 30 chunks by cosine distance (ready documents of the
   notebook, optionally restricted to `document_ids`).
2. **Keyword list:** top 30 by `ts_rank_cd(content_tsv, q)` where `q` is the
   question's terms OR-ed together:
   `replace(plainto_tsquery('english', :text)::text, '&', '|')::tsquery`.
   If the question has no searchable terms (only stop words), this list is empty.
3. **Fusion:** reciprocal rank fusion, `score = Σ 1 / (60 + rank)` over the lists
   a chunk appears in; return the top `top_k` (default `TOP_K` = 6) with their
   documents, best first.

Callers: chat (unchanged behaviour otherwise) and study generation (§4.3).

### 2.3 Verification

A PDF where an exact code (e.g. `BCSE301L`) appears once in a long page among
unrelated text; a question naming the code retrieves and cites that page. Chat
answers on the existing Module 5 notebook still cite correctly.

## 3. OCR for scanned pages

### 3.1 Library

`rapidocr-onnxruntime` (CPU, models bundled in the wheel, works offline).
Docker image adds `libgl1` and `libglib2.0-0` for OpenCV. The OCR engine is a
lazy process-wide singleton, like the embedding model.

### 3.2 Pipeline change (`pdf_parser` + `ingest`)

- For each page: take the text layer; if it has fewer than 20 non-whitespace
  characters, render the page with PyMuPDF at 200 DPI and OCR it; join the
  recognised lines in reading order.
- Mixed documents work page by page. OCR runs inside the existing worker thread.
- Each page records whether it was OCR'd; the document gets `ocr_pages`
  (int, migration `0002`) so the UI can say "3 pages read with OCR".
- Failure message when no page yields text even after OCR:
  "No readable text found, even with OCR."
- While processing, the source row shows "Reading and indexing…" (unchanged);
  OCR makes processing slower (~1–3 s per scanned page), not different.

### 3.3 Viewer behaviour

OCR'd pages have no pdf.js text layer, so citations open the correct page
without a highlight (existing fallback). The source list shows
"N pages, M read with OCR".

### 3.4 Verification

The image-only test PDF (today: failed) becomes ready; a question about its
content gets a cited answer that opens the right page. A PDF with real text is
unaffected (no OCR runs, same speed). Docker image builds and OCRs offline.

## 4. Study tools: quizzes and flashcards

### 4.1 Data (migration `0002`)

`study_sets`:

| Column | Type | Notes |
|---|---|---|
| `id` | uuid pk | |
| `notebook_id` | fk → notebooks, cascade | indexed |
| `kind` | `quiz` \| `flashcards` | |
| `title` | text | generated by the model, ≤ 120 chars |
| `topic` | text null | the optional focus the user typed |
| `document_ids` | jsonb | sources chosen at generation time |
| `items` | jsonb | see 4.2 |
| `last_score` | int null | quizzes only |
| `created_at` | timestamptz | |

Creating a set bumps the notebook's `updated_at`.

### 4.2 Item shapes (stored and returned)

Quiz item: `{question, options: [4 strings], answer_index: 0–3, explanation, source}`.
Flashcard item: `{front, back, source}`.
`source` = the same shape as chat sources (`marker, chunk_id, document_id,
filename, page_number, snippet`).

### 4.3 Generation

`POST /notebooks/{id}/study-sets` body:
`{kind, count, topic?: str (≤ 200), document_ids?: [uuid]}`;
`count` ∈ {5, 10, 15} for quizzes, {10, 20, 30} for flashcards.

1. Validate ownership; `document_ids` must be ready documents of this
   notebook (default: all ready documents); none ready → 400
   "Add a ready source first".
2. **Select excerpts within a budget of ~16,000 characters (~4,000 tokens):**
   - With a topic: hybrid search for the topic, up to 18 chunks.
   - Without: an even spread — order the selected documents' chunks by
     (document, page, chunk_index) and take every n-th so up to 18 chunks
     cover the material start to end.
   - Stop adding chunks once the character budget is reached.
3. Label excerpts `C1…Cn` (same `build_context` as chat).
4. One Groq call (non-streamed, JSON object response format,
   `max_tokens` 6,000) with instructions: produce exactly `count` items, each
   grounded in one excerpt and citing it as `"cite": "C3"`; quiz options
   plausible with exactly one correct; plus a short `title`.
5. Parse and validate with Pydantic: drop items that are malformed, have a
   `cite` not in the map, or (quizzes) don't have 4 distinct options and a
   valid `answer_index`; shuffle quiz options server-side so the answer
   position is uniform. Invalid JSON → one retry. Fewer than half the
   requested items valid → 502 "Couldn't generate a good set — try again".
6. Save and return the set (201).

Errors reuse chat's mapping: Groq 429 → HTTP 429 with `Retry-After` and
the rate-limit message; auth/outage errors → 502 with the friendly message.

### 4.4 Other endpoints

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/notebooks/{id}/study-sets` | List (newest first): id, kind, title, topic, item count, last_score, created_at |
| GET | `/api/study-sets/{id}` | Full set with items |
| DELETE | `/api/study-sets/{id}` | Delete (204) |
| POST | `/api/study-sets/{id}/score` | `{score}` (0…item count), quizzes only → updated set |

All owner-checked through the notebook; another user's set → 404.

### 4.5 Frontend

- **Chat | Study** segmented switch in the centre panel header (desktop and
  mobile tab). Chat state is kept when switching.
- **Study home:** "New quiz" and "New flashcards" buttons; list of saved sets
  (title, kind, N questions/cards, date, "Last score 7/10"); menu → Delete
  (confirm). Empty state explains what study sets are.
- **Generate form** (inline panel): source checkboxes (ready sources, all
  checked), optional topic input, count selector, Generate button →
  progress state ("Writing 10 questions from 3 sources…"); 429 shows the
  countdown + Retry; other errors show the message.
- **Quiz player:** progress "Question 3 of 10"; four option buttons; on pick:
  correct/incorrect styling, the explanation, and a citation chip (opens the
  PDF viewer at the page); Next; final screen with score, "Retake" and
  "Back to study"; score is posted on completion. Keyboard: 1–4 to answer,
  Enter for next.
- **Flashcard player:** one card, click/Space flips (respecting reduced
  motion), ←/→ navigate, Shuffle, "Card 4 of 20"; back side shows the
  citation chip.
- Citation chips reuse `CitationChip`; opening uses the workspace's existing
  viewer logic.

### 4.6 Verification

On the user's Module 5 notebook (or the Module 5 test PDF): a topic-focused
quiz ("boundary value analysis") and a 20-card deck generate within the token
limit, every item cites a page that opens correctly; answering a quiz saves
the score and reload shows it; delete works; user B gets 404 for user A's
set; a simulated 429 shows the countdown; mobile layout works.

## 6. Out of scope

Multiple chats per notebook, summaries/study guides, automatic notebook
overview, non-PDF sources, written-answer or true/false questions, spaced
repetition scheduling, sharing study sets, OCR text highlighting in the viewer.
